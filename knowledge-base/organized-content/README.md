# 整理后的知识内容（organized-content）

> **文档类型**：Reference（参考资料）
> **更新频率**：知识库迭代时
> **维护者**：AI自动维护
> **读者**：AI代理+人类

本目录存放**整理后的知识内容**，是飞书知识库的源头和备份。

---

## 目录结构

```
organized-content/
├── 做题思路解析.md              # 通用做题方法论（面向所有课程）
├── <章节名>/
│   ├── README.md                # 章节概览（含子节点链接、同步状态）
│   ├── 知识拆解.md              # 核心知识点（定义、分类、原则、表格）
│   └── 考试指导.md              # 考点分析、做题技巧、易错点、记忆口诀
└── README.md                    # 本文件
```

> 验证/同步默认不单独成文（验证结论并入任务报告），章节目录不常驻「验证报告_*.md / 同步报告_*.md」；仅视频/转写等非标准对象专项质检确需留痕时才按需出现 VERIFICATION.md。

---

## 文件类型与用途

| 文件类型 | 命名模式 | 用途 | 同步飞书 |
|---------|---------|------|---------|
| **章节README** | `README.md` | 章节概览，含子节点链接和同步状态 | ✅ 作为父节点页面 |
| **知识拆解** | `知识拆解.md` | 核心知识点，按考点组织 | ✅ 作为知识节点 |
| **考试指导** | `考试指导.md` | 考点分析、做题技巧、易错点 | ✅ 作为考试指导节点 |

> 验证/同步为必做动作但默认不单独成文，结论并入《任务报告》；章节目录不常驻验证/同步报告。

## 使用场景

### 1. 同步到飞书知识库（主要用途）

```
organized-content/（本地源头）
    ↓ 同步
飞书知识库（用户使用）
```

**原则**：本地有，则同步到知识库。所有知识库内容必须先在本地完成并验证，再同步到飞书。

### 2. 做题验证

做题时查询本地知识库内容，验证答案：
- 单选题答案是否正确？→ 查 `知识拆解.md`
- 多选题是否漏选？→ 查 `考试指导.md` 中的易错点
- 考点是否掌握？→ 查章节 README 中的重点内容

### 3. 学习参考

用户学习时直接阅读：
- 先读章节 README 了解概览
- 再读 `知识拆解.md` 掌握核心知识点
- 最后读 `考试指导.md` 了解考点和做题技巧

### 4. 知识库迭代

知识变更或补充时：
1. 先更新本地 `organized-content/`
2. 验证更新后的内容
3. 再同步到飞书知识库
4. 同步后回读校验，结论并入任务记录（默认不单独写同步报告）

## 与 source-materials 的关系

| 维度 | source-materials/ | organized-content/ |
|------|-------------------|-------------------|
| 性质 | 原材料 | 成品 |
| 内容 | 原始、未整理 | 整理、提炼、结构化 |
| 用途 | 加工、追溯、验证 | 直接使用、同步飞书 |
| 生成方式 | 做题时自动记录 | AI整理提炼 |

## 质量保证

### 生成前检查

- [ ] 来源材料完整（题答 papers JSON、解析、用户笔记）
- [ ] 与讲义内容核对（冲突时以讲义为准）
- [ ] 知识点覆盖完整（无遗漏考点）

### 生成后验证

- [ ] 知识拆解：定义准确、分类清晰、表格完整
- [ ] 考试指导：考点分析到位、易错点实用、记忆口诀有效
- [ ] 章节README：子节点链接正确、同步状态准确
- [ ] 做题验证：用知识库做题正确率 > 90%

### 同步前检查

- [ ] 本地内容已验证通过
- [ ] 飞书知识库节点结构正确
- [ ] 父节点页面含子节点链接
- [ ] 同步后内容与本地一致

---

## 注意事项

1. **本地是源头**：所有知识库内容必须先在本地完成，再同步飞书
2. **不要直接改飞书**：飞书知识库的修改应先改本地，再同步
3. **验证/同步不单独成文**：默认并入任务报告；如确需留档仅本地、不上传飞书
4. **父节点必须有链接**：章节 README 必须包含知识拆解和考试指导的链接
5. **冲突处理**：当用户留言与讲义冲突时，以讲义为准
