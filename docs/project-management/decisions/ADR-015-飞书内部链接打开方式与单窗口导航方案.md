# ADR-015: 飞书知识库内部链接打开方式与单窗口导航方案（保留 cite + 导航页引导左侧目录树）

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI自动维护 + 用户审核
> **读者**：AI代理+人类

## 状态

已采纳（2026-09-07）。适用于所有同步到飞书知识库的课程（税法已落地，会计等后续课程直接遵循）。本决策不改变 ADR-012 的三层结构，只规定"飞书正文内部链接用什么写、打开方式如何对待、单窗口阅读如何引导"。

## 背景

用户对课程总览页提出两点体验诉求：①点击章节/知识点链接尽量在**同一窗口**导航，不要不断新开标签导致迷失；②每章进入各自对应位置，不能 14 行都指向同一篇全局速查（诉求②由总览改造与 ADR-012 三层结构解决，本 ADR 聚焦①）。

排查过程中走过一次弯路，必须固化为教训：

1. **早期误判（commit 5947c45）**：把全库站内链接从完整 URL 改为 `<cite type="doc">` 后，仅依据"回读 DOM 为 `target="_self"`、0 个 `_blank`"就判定"已实现当前窗口打开"。用户真人点击后反馈仍新开标签，该结论被推翻。
2. **可信复测**：改用 ADR-010 选定的真实 Chrome + puppeteer-core CDP 通道，以 `page.mouse.click()`（底层 `Input.dispatchMouseEvent`，`isTrusted=true`，飞书无法区分真人）逐种实测，结论确定：

| 正文区写法 | 真人/可信点击结果 |
|-----------|------------------|
| `<cite type="doc">` 内部引用 | 新开标签 |
| `<button action="OpenLink">` | 新开标签 |
| `<bookmark>` 书签卡片 | 新开标签 |
| 普通 `<a href>` 完整 URL | 新开标签 |
| 原生 `<sub-page-list/>` 子页面列表 | 新开标签 |
| **左侧知识库目录树节点** | **标签数不变、当前页 URL 直接切换（唯一本窗口）** |

3. **官方佐证**：lark-cli 仓库 issue #2399（2026-08-19 起仍 open）确认 API 写入的跨文档/锚点链接即新开；期望中的 `docsLink`（ParagraphElement.docsLink）只解决**同一篇文档内**锚点滚动，且当前 CLI 版本尚未支持。飞书"设置→效率→优先打开方式"只控制桌面端"飞书内打开 vs 跳浏览器"，不控制"当前标签 vs 新标签"，网页版不适用。Markdown 导入的页内锚点/相对路径/`[[]]` 双链全部降级为纯文本不可点，也无特殊跳转。

**核心方法论教训**：DOM 的 `target` 属性 ≠ 真实导航行为（飞书 React 的 onclick 统一接管）；`dispatchEvent`/`element.click()` 合成事件因 `isTrusted=false` 会被飞书拦截，同样不能作为结论依据。判定"点击后到底怎么开"只能靠 CDP 可信点击，观察点击前后可见标签页数量与当前页 URL。

## 决策

### 1. 站内导航统一用 `<cite>`，但理由是"结构化可校验"而非"能本窗口打开"

- 指向知识库内其他文档一律 `<cite type="doc" doc-id="obj_token"/>`（obj_token 取台账第 3 列），由 `wiki_link_resolve.py` 从本地相对链接自动转换；
- 选 cite 而非完整 URL 的真实理由：渲染为目标文档标题、obj_token 强绑定、可回读自动校验 0 坏链；完整 URL 冗长、易随节点变动失效，**仅用于站外链接**。
- 明确记录：cite 与完整 URL **打开方式相同（都新开标签）**，今后不得再以"cite 能当前窗口打开"作为选择或验收理由。

### 2. 接受"正文跨文档必新开"为平台事实，不再重复试错

上表 5 类正文写法已全部证伪，后续课程不再尝试换写法实现正文内本窗口跳转；唯一本窗口入口是左侧知识库目录树。若未来 lark-cli 落地 `docsLink` 或飞书改变前端行为，再用 CDP 可信点击复测后重新评估。

### 3. 采用方案 B：保留 cite，仅在导航型页面顶部加单窗口引导（方案 A 否决）

- **方案 B（采纳）**：全部 cite 原样保留，只在**导航型页面**顶部加一段导航说明，如实告知"正文引用点击新开标签，想单窗口连续阅读请用左侧知识库目录树"：
  - 课程总览页 1 处 + 14 个章 README 各 1 处，共 15 处；
  - 92 篇知识点详解 + 2 篇全局资料是**纯内容页，不加**，避免 94 处重复堆砌（遵循"以精简删冗余为荣"）。
- **方案 A（否决）**：总览去链接化、导航全部交给左侧树。否决原因：牺牲正文内的可点达性与上下文跳转，且左侧树深层知识点需逐层展开，阅读中引用并不方便；B 在"保留可达性"与"给出单窗口路径"间更平衡。

### 4. 验证分两层，各用各的权威手段

- **链接正确性**（指向对不对、有无坏链）：`docs +fetch` 回读，按 doc-id 与台账 obj_token 逐行比对、统计残留完整 URL（见 `wiki-link-verification-sop.md`）；
- **打开方式**（点了怎么开）：仅在怀疑前端行为变化时用真实 Chrome CDP 可信点击抽检，**禁止**用 DOM `target` 属性或合成事件下结论；
- 导航型页面还需校验"导航说明块存在"，纯内容页校验其"不存在"。

## 与历史 ADR 的关系

- **承接 ADR-010**：本决策的可信点击结论依赖 ADR-010 选定的 puppeteer-core/CDP 连接日常 Chrome 通道；没有可信输入就无法推翻 DOM 假象。
- **承接 ADR-012**：飞书与本地同构（章父节点 / 知识点子页面）不变，本 ADR 只规定这些节点之间"链接怎么写、怎么验、怎么引导单窗口"。
- **修正 commit 5947c45 的立论**：该提交"cite=本窗口"的前提错误，其 cite 改法本身正确并保留（commit 5e9af46），但相关脚本注释、SOP、模板、API 文档中的"当前窗口打开/target=_self"表述已全部改为本决策口径。

## 后果

### 正面
- 用户有明确、可靠的单窗口阅读路径（左侧目录树），正文内也保留了可点的文档引用；
- 会计等后续课程建库时直接遵循本决策与已内置导航块的 `PARENT_NODE_TEMPLATE.md`，不必再重走"试 5~6 种写法→逐个 CDP 实测"的弯路；
- 沉淀"验证必须落在用户真实感知层、DOM 属性不等于行为、合成事件不可信"的通用范式，避免同类返工。

### 负面
- 正文点击仍会新开标签，这是平台限制，只能引导、无法在正文层根治；
- 总览与 14 章 README 各多一段导航说明块（已用"仅导航页加、内容页不加"把冗余压到最小）。

### 后续
- 会计课建库时：`build_course_overview.py` 当前硬编码税法 14 章/课程信息，需参数化泛化（章节表、课程元信息外置），导航说明逻辑可直接复用；
- 跟踪 lark-cli issue #2399：若 `docsLink`（同文档锚点）或跨文档本窗口能力落地，CDP 复测后评估是否升级方案；
- 每次同步后按 `wiki-link-verification-sop.md` 执行：回读 doc-id 比对 + 导航说明存在性检查，必要时 CDP 可信点击抽检。
