# ADR-012: 课程数据三层解耦与按官方知识点聚合（替代"按讲端到端、一讲双文档"）

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI自动维护 + 用户审核
> **读者**：AI代理+人类

## 状态

已采纳（2026-09-04）。本决策是课程数据组织与主流程的**范式级变更**，演进 ADR-004 / ADR-005 / ADR-011（见"与历史 ADR 的关系"），不改写其原文。

## 背景

旧范式（ADR-004"知识拆解/考试指导双文档" + 以讲为单位组织）下，**一讲是最小加工单元**：每讲独立端到端走一遍，讲目录内混放 video/transcript/docs/docs_text，产出 `知识拆解.md`+`考试指导.md` 两份文档。实践暴露出四点结构性问题：

1. **资源与讲次并非一一对应**。39 讲中仅 17 讲名下挂讲义、22 讲为空，且存在横跨两个模块的"混合讲"（如讲29＝个税(5)+征管(1)），连"是否混合讲"都无法靠标题/编号推断（ADR-011 已用 syllabus 接口证实）。"一条目一目录"因此不得不叠加 `lecture-resource-map` 这类人工别名层来补救。
2. **知识点天然跨讲**。116 套卷 1296 题去重后只有 92 个官方知识点，同一知识点散落在连续多讲；按讲切割会把同一知识点拆碎、重复、前后不一致。
3. **过程件散落、清理无门禁**。`.vfetch`（下载分片）散在每个讲目录，papers / cdp-sniff / 各类台账散在 data 顶层，日志、转写临时散在仓库根，缺少统一的临时层与清理判定。
4. **主观大题按顶层提取会漏**。55 道主观大题（questionType=5）顶层 `answer/analysis/knowledgePointList` 为空，真正的答案与知识点在 `subQuestionList` 小问层（questionType=6）；只看题顶层会误判"无答案/无标签"。

本地数据已足以支撑范式切换，关键事实均由本地数据现算（无需先回官网）：

- 39 个视频、17 份讲义（以 syllabus 接口 `discriminator` 判别为准，不靠编号推断）；
- 116 套卷、1296 题；客观题 95%（1241 题）顶层带官方知识点标签，去重得 **92 个官方知识点、归 14 个官方模块组**；
- 55 道主观大题共 390 个小问，`answer` 与 `analysisText`（真正答案/算式）100% 非空、389 个小问带知识点；
- 小问层仅多出 1 个顶层没有的泛标签 id=112376"应纳税额的计算"，它被 157 个小问引用、来源卷仅两份且全部为增值税语境，等价归并到"增值税一般计税方法应纳税额的计算"，**知识点总数维持 92**。

## 决策

### 1. 课程数据分三层（均位于 `data/课程库/<课程名>/`，业务数据不入 Git）

- **`原始资源/`（永久层，传网盘）**：按资源类型分桶，不按讲混放。
  - `videos/NN_讲题/{video.mp4, transcript.md, transcript.json}`；
  - `notes/NN_模块/{讲义.pdf, OCR.md}`（讲义按知识模块全局唯一，保留官网原名；空讲不复制）。
- **`知识详解/`（成品层，可迭代，传网盘并同步飞书）**：14 官方模块组 → 92 官方知识点。
  - **一个知识点 = 一篇 md**，文件名用官方知识点原名；篇内固定四个二级标题：`一、知识拆解` / `二、考试指导` / `三、题答解析` / `四、学员补充`（无内容的节可省）；
  - 课程级两篇全局成品：`课程做题思路解析.md`、`考试指导速查手册.md`；课程库层一份跨课的 `通用做题思路解析.md`。
- **`_workspace/`（临时层，Git 忽略 + 网盘排除）**：英文子目录 `manifest/ papers/ sniff/ user-notes-raw/ logs/ tmp/`，运行中再生成的过程件/临时/日志统一收此管理，双门禁后分级清理（详见 finalize SOP）。

### 2. 加工单元从"讲"改为"官方知识点"，采集与生成解耦

- 资源采集按资源类型独立进行，知识生成**跨讲按知识点聚合**，两者不再绑定为"一讲端到端"；
- 层间靠 **`_workspace/manifest/course-manifest.json`** 维系：记录"讲次 ↔ 资源(视频/讲义/试卷) ↔ 知识点"的完整映射，并承载知识点等价/归并映射；它由 syllabus 接口报文 + papers 经脚本生成、可 rebuild、可校验。

### 3. 题答提取分客观/主观两型

- 客观题（type=1 单选、type=2 多选等）取顶层字段；
- 主观大题（type=5 容器）必须**下钻 `subQuestionList`**，按"大题题干 → 各小问（题干 + analysisText 答案解析 + 小问知识点）"组织进对应知识点篇的"三、题答解析"；
- 知识点等价归一：id=112376"应纳税额的计算" → "增值税一般计税方法应纳税额的计算"（记入 course-manifest，不单独开篇）。

### 4. 分类骨架直接用官方知识点，禁止 AI 自造

- 14 组编号按官方教材/课件模块序 01–14，组内为官方知识点；92/14 由脚本从 papers 的 `knowledgePointList`（含小问层）现算并 assert 无遗漏、无未归类；
- 已知归并特例：土地增值税归组10（不得被"增值税"误归组02）；委托加工/应税消费品/进口环节消费税归组03；非居民企业归组04；非居民个人归组05。

### 5. 主流程改为四阶段，飞书统一同步

- ①资源采集 → ②试卷采集与 manifest 生成 → ③知识详解生成（核心）→ ④收尾（双门禁校验 → 清 _workspace → 网盘备份 → 同步飞书知识库）；各阶段配套 SOP；
- 飞书与本地**同构**（14 组＝父节点、知识点篇＝子页面）；采用"本地全量生成并校验后统一同步、冲刺模考后做最终一次同步"，**替代旧的分讲同步**；
- 冲刺模考（3 张 48 题）是做题/交卷的特殊分支，必须在所有基础作业完成后才进行，其题/答同为知识来源、末期并入。

### 6. Git 不再版本化课程成品

- 旧 `knowledge-base/organized-content/`（讲级/按章旧成品）与 `knowledge-base/source-materials/`（早期来源区）**迁移期作为阶段③的输入**：旧成品中质量好的"知识拆解骨架"被复用、其中用户留言先归到 `_workspace/user-notes-raw/`，官方解析以 papers 为准；待知识详解 92 篇生成并校验、留言全部吸收后，这两个区清退；
- 此后课程成品统一落在 `data/`（本地）→ 网盘 → 飞书；**Git 只保留生产知识的规范/模板/SOP/脚本与文本治理件，不存某门课的成品**。

### 7. 数据获取优先级

优先使用本地已有的正确数据完成改造；仅当本地缺失、取用不便或成本更高时，才经日常 Chrome（CDP）从官网补取。

## 与历史 ADR 的关系

- **演进 ADR-004**："知识拆解 / 考试指导"由**两份独立文档**演进为**一篇知识点 md 内的两个节**，并新增"题答解析""学员补充"两节（知识与应试从"分文档"改为"分节"）。
- **演进 ADR-005**：明确三层各自的 GitHub/本地/网盘/飞书归属——原始资源与知识详解传网盘、知识详解同步飞书、_workspace 三处都不传、Git 只版本化文本规范与脚本。
- **演进 ADR-011**：入库的逐讲课件别名 `lecture-resource-map.json` 被覆盖更全的 `course-manifest.json`（讲↔资源↔知识点）取代。ADR-011 第 4 条曾以"轻量派生元数据应入库"为由将 map 放入 Git；本决策修正为：**course-manifest 与具体课程数据强绑定、换课或官方调整即变、且可由 syllabus+papers 脚本完全 rebuild，属课程过程件，放 `_workspace/manifest/` 不入库；入库的是"如何生成 manifest 的规则与脚本"，而非某门课的 manifest 实例。**

**本决策同时记录被否决的备选**：①"考点图谱"来源——经侦查只给"章→考点"目录归属、不含知识点之间关系，已否决；②`_待补标/` 过渡文件夹——主观题答案本就在小问层、不存在采集缺口，无需过渡；③34 章人工映射——直接采用官方 14 模块/92 知识点，`chapter-mapping-draft.md` 作废，其"以官方为准、不 AI 自造"的有效原则并入知识库组织规范。

## 后果

### 正面
- 资源采集与知识生成解耦，混合讲/空讲/跨讲知识点不再需要人工别名补救；
- 同一知识点只在一处聚合、跨讲一致，并天然对应飞书"组父节点 → 知识点子页面"；
- 过程件集中 `_workspace`、清理有明确双门禁，讲目录与仓库根保持干净；
- 主观大题不再漏提取；成品可由"原料 + 脚本"重新生成。

### 负面
- 需要一次性存量迁移（旧讲目录混放、organized-content、source-materials → 三层），有迁移成本；
- 生成知识详解前必须先有 course-manifest，多一个显式索引层（但可自动生成、可脚本校验）；
- 配套的组织规范、模板、命名规范、四阶段 SOP 需成套改写。

### 后续
- 图纸先行：批1 ADR-012 + WORKFLOW；批2 组织规范/模板/目录结构/命名；批3 四阶段 SOP，旧单讲 SOP 与 34 章映射标废弃；批4 同步全部引用；
- 图纸验收通过后，才出《存量迁移 + course-manifest 生成方案》，最后做脚本与数据落地。
