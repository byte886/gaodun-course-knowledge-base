## 总体流程

```
建目录 → 下载视频 → 压缩视频 → 压缩验证 → 下载文档 → 内容解析(视频转写+讲义OCR) → 做题/交卷(多种模式，含基础作业) → 同步百度网盘 → 知识库一次性生成 → 同步飞书知识库
```

**特殊模式：冲刺模考**（做题/交卷的一种特殊模式，所有讲次的基础作业完成后触发）：
```
冲刺模考视频解析 → 冲刺模考做题/交卷 → 题/答/解析采集 → 知识库迭代更新 → 更新考试指导速查手册 → 同步飞书知识库
```

**核心原则**：
1. 每个讲座独立走完一遍基础流程，完成后再进入下一个
2. 知识库一次性生成：收集所有来源（讲义OCR + 视频转写 + 题/答/解析 + 用户笔记）后一次性生成，不做两阶段
3. 做题/交卷包括多种模式（知识点测试/课后练习、分章真题测、强化专题、冲刺模考）；**冲刺模考是特殊模式，必须在所有课程/讲座与基础作业完成后才进行**
4. 做题/交卷的首要目的是帮用户把作业100%正确完成，题/答/解析再反哺知识库

## 每讲流程检查清单（强制，必须执行）

### 为什么需要

无论是走完整流程还是中途补齐流程，每讲完成后**必须**执行本检查清单，确保所有步骤都已完成，避免遗漏（如上传网盘、视频转写等关键步骤）。

**历史教训**：2026-09-03 知识库重建时，因缺少强制检查机制，中途补齐流程遗漏了"上传百度网盘"步骤，导致部分讲次的视频未备份到网盘。

### 检查规则

1. **每讲完成后必须执行**：无论是完整流程还是中途补齐，每讲的所有操作完成后，必须逐项核对本清单
2. **中途补齐时先检查再执行**：如果是中途补齐某讲，先执行本检查清单，确认哪些步骤已完成、哪些缺失，然后只执行缺失的步骤
3. **所有步骤必须标注状态**：已完成✅ / 未完成❌ / 不适用N/A
4. **检查结果记录到任务总结**：每讲的检查结果必须在对话中总结
5. **未完成的步骤必须说明原因**：如果某步骤标记为未完成或不适用，必须说明原因

### 检查清单

| 序号 | 步骤 | 必须/可选 | 检查内容 | 状态 |
|------|------|----------|----------|------|
| 1 | 建目录 | 必须 | 目录结构符合规范，命名正确，无空目录 | ☐ |

### 中途补齐流程的特殊规则

如果是中途补齐某讲（不是从建目录开始的完整流程），按以下规则执行：

1. **先执行检查清单**：逐项核对，确认哪些步骤已完成、哪些缺失
2. **只执行缺失的步骤**：不要重复执行已完成的步骤
3. **执行后重新检查**：缺失的步骤执行完成后，重新执行检查清单，确认所有步骤都已完成
4. **记录补齐过程**：在任务总结中记录补齐了哪些步骤、为什么之前遗漏

### 批量任务的检查规则

如果是批量处理多个讲次，按以下规则执行：

1. **每讲单独检查**：每个讲次完成后，立即执行该讲的检查清单
2. **批量任务完成后总检查**：所有讲次处理完成后，执行一次总检查，确认所有讲次的所有步骤都已完成
3. **总检查清单**：
   - 所有讲次的视频都已下载、压缩、验证
   - 所有讲次的文档都已下载
   - **所有讲次的视频和文档都已上传到百度网盘**
   - 所有讲次的视频都已转写
   - 所有讲次的讲义都已OCR
   - 所有讲次的作业都已完成，题/答/解析已采集
   - 所有讲次的知识拆解和考试指导都已生成
   - 所有讲次的内容都已同步到飞书
   - 任务总结已完成

## 全局规则（所有环节必须遵守）

### 大任务检查与报告约定（必须遵守）

**核心原则：子任务主动上报 + 定期检查防异常，两者结合。**

1. **子任务主动上报（主要方式）**：子任务完成后立即主动上报结果（成功/失败、输出文件、关键指标）。这是主要的报告方式。
2. **定期检查（兜底方式）**：对于预计运行时间超过5分钟的任务，**最大5分钟检查一次**，目的是**防止异常**（任务卡住、进程异常退出、不主动上报等），不是为了报告进度。
3. **定期检查不输出"还在运行中"**：如果一切正常，不需要在对话中反复报告进度，只在子任务完成后上报最终结果。
4. **发现异常立即处理并上报**：定期检查发现异常（进程退出、文件大小不增长、错误日志），立即处理并上报。

**检查内容**（定期检查时）：进程是否在运行、输出文件大小是否增长、是否有错误日志。

**异常处理**：进程异常退出→删除不完整文件→重新启动；文件大小不增长但进程还在→检查是否卡住→必要时重启。

### 文档健康度检查（必须遵守）

**每次大任务完成后，必须执行文档健康度检查，确保文档体系的完整性、关联性和质量。**

**详细规范**：[DOCUMENTATION_OPTIMIZATION.md 第十二章](project-management/standards/DOCUMENTATION_OPTIMIZATION.md)

**必须执行文档健康度检查的场景**：
1. 每个课程/每个大任务完成后
2. 项目结构重大调整后
3. 新增/删除/移动大量文档后
4. 用户明确要求检查时

**检查内容**：
1. 完整性：所有文档是否在DOCUMENTATION_MAP.md中有记录，新增文档是否有类型标注
2. 关联性：文档中的链接是否有效，是否存在文档孤岛
3. 结构：目录结构是否与DIRECTORY_STRUCTURE.md一致，是否存在空目录
4. 质量：是否存在重叠内容，大文档是否需要分解
5. 维护：.gitignore是否合理，核心文档是否最新

**自动化保障**：
- pre-commit hook自动检查文档关联性和类型标注
- 每次git提交前自动触发，不需要手动执行

### 飞书同步策略（必须遵守）

**核心原则：分讲同步 + 最后总同步，不做所有课程完成后一次性同步。**

| 同步时机 | 同步内容 | 目的 |
|---------|---------|------|
| 每讲完成后 | 该讲的知识拆解、考试指导、父节点内容 | 及时同步，避免最后一次性同步的风险，方便用户随时查看 |
| 所有讲次完成后 | 考试指导速查手册（横向汇总所有讲次） | 顶层索引页，需要所有讲次完成后才能生成 |
| 冲刺模考完成后 | 冲刺模考的题/答/解析、更新考试指导速查手册 | 冲刺模考是最后阶段，完成后补充到知识库 |

**为什么不做"所有课程完成后一次性同步"**：
1. 一次性同步34讲的内容，风险较大（网络问题、API限流、内容错误等）
2. 如果同步失败，难以定位是哪一讲的问题
3. 用户无法在过程中查看已完成的内容

**同步要求**：
- 先本地生成，验证通过后再同步飞书
- 同步后必须执行结构检查：节点层级、重复节点、空节点、父节点链接
- 禁止直接在飞书知识库中编辑内容（除非紧急修复），必须用API同步

3. 知识库内容已同步飞书知识库并验证
4. 临时文件确实不需要了（不是正在使用的文件）

### 多任务并发调度（必须遵守）

**核心原则：依赖关系定顺序，实测数据定并发，事件驱动触发衔接，总调度实时决策。**

**四条核心原则**：
1. **大任务必须完整拆解为 DAG**：任何大任务先拆解为子任务节点，标注依赖关系（Linear Chain顺序依赖、Fan-Out扇出并行、Fan-In扇入汇聚），每个节点标注任务名、依赖、预估时长、资源类型、最优并发度、状态
2. **除依赖外，必须评估任务时长并按需测试**：经验估算（任务特性已知）、小样本测试（测试成本低但影响大）、历史数据复用（同项目同环境已跑过）；不是所有任务都要测试，测试成本低但影响大的必须测
3. **总调度必须实时调度，任务完成即通知**：阶段内用 `xargs -P N` 做动态调度（内核级，无竞态），阶段间用事件监听（watch_stage_done.sh），总调度维护 DAG 状态，收到完成标记后检查下游依赖是否满足，满足即启动；**禁止人工长间隔巡检**
4. **并发度必须基于实测，不能凭核数估算**：CPU密集任务的最优并发度往往远低于物理核数（受内存带宽、CPU cache、GIL等影响）；用四步实测法（单进程基线→逐步加并发→对比总吞吐→选最优），若串行总吞吐最高则串行就是最优

**本项目已验证的并发特性**：
| 任务类型 | 资源瓶颈 | 最优并发 | 说明 |
|---------|---------|---------|------|
| FunASR转写 | CPU+内存带宽 | 1（串行） | 小模型推理受cache争用，并发反降 |
| x265视频压缩 | CPU（11核/实例） | 1（全局单实例） | 单实例已吃满多数核 |
| macOS Vision OCR | CPU（1核/实例） | 可与压缩并行 | 单实例只吃1核，压缩之余可跑1-2个 |
| 视频下载/解密 | 网络IO | 可并发（20分片） | CDN静态资源，等同真实播放器 |
| 抓HLS key | Chrome单标签 | 必须串行 | 同一Chrome一次一个播放标签 |
| AI API调用 | 网络IO+API限流 | 按章并发 | 非CPU瓶颈，受API速率限制 |

**任务队列实现**：
- **禁止自建 flock 队列**：macOS bash 函数内 flock 在多进程子shell下存在竞态，会导致多个worker重复取到同一任务
- **统一使用 xargs -P**：由内核管理并发和任务分发，无竞态、自动负载均衡
  ```bash
  cat pending.txt | xargs -P 3 -n 1 bash scripts/process_one.sh
  ```

**可并行的任务组合**（在主流程中）：
- 视频压缩（CPU密集，全局1实例）运行期间，可并行跑 OCR（1核/实例，1-2个）
- 视频下载（IO密集）可与其他不依赖视频的任务并行
- 多讲次的 OCR 可并行（1-2个并发）
- 多讲次的视频下载可并行（受网络带宽约束）

**换环境/换模型时**：CPU密集任务的并发度必须重新实测，不能直接套用本项目结论。

**关联文档**：
- **任务规划与并行调度方法论**：[task-planning-and-parallel-scheduling.md](development/methodology/task-planning-and-parallel-scheduling.md) — DAG拆解、时长评估、实时调度、并发度实测、落地检查清单

## 4. 内容解析

### 摘要

将视频音频转写为文字，将讲义文档（图片型PDF）通过OCR提取文字，为知识库生成提供素材。

### 4.1 视频转文字

- **方案**：阿里FunASR（SenseVoiceSmall），开源本地方案，0成本
- 中文CER 8-10%，VAD加速后约15x实时（2.5小时视频约10分钟）
- 虚拟环境：`transcription/venv/`，脚本：`scripts/transcribe_pipeline.py`（单视频）、`scripts/batch_transcribe.sh`（批量）
- 必须在iTerm中运行
- **并发特性**：FunASR是CPU密集任务，**串行最优**（单进程吃2核，并发因内存带宽+cache争用导致总吞吐下降）；禁止多开并发转写；详见[多任务并发调度](#多任务并发调度必须遵守)和[parallel-processing-guide.md](development/performance/parallel-processing-guide.md)

### 4.2 文档文字提取（OCR）

- **方案**：macOS Vision框架OCR（系统原生免费），**不是tesseract**
- **工具分工**：
  - PyMuPDF（200 DPI）：仅用于将PDF转为图片，不做OCR
  - Swift编译的`/tmp/ocr_vision`：使用macOS Vision框架做OCR识别
- 性能：116页约2分钟，每页约1秒
- 遇到表格/公式/图表时用AI视觉补充识别
- 批量脚本：`scripts/batch_ocr.sh`
- **并发特性**：OCR是CPU密集任务（单实例吃1核），可与视频压缩并行（压缩吃11核，OCR吃1核）；多讲次OCR可1-2个并发；详见[多任务并发调度](#多任务并发调度必须遵守)

### 参考文档

- **转写指南**：[transcription.md](development/tools/transcription.md) — FunASR环境配置、性能数据、脚本使用
- **OCR指南**：[ocr.md](development/tools/ocr.md) — macOS Vision框架、PDF转图片、表格图表AI补充

## 5. 做题/交卷（帮用户完成作业，多种模式）

### 摘要

通过接口完成作业，帮用户把作业100%正确完成。**做题链路已接口化（2026-09-02）：redo-paper 进卷即返回题面、标准答案与解析，submit-paper 一次性交卷，exam-report 回查，全程纯接口、无需 UI 点选；Playwright UI 仅用于登录与未覆盖异常兜底。** 题/答/解析再反哺知识库。

**做题/交卷包括多种模式的作业**：
| 模式 | 说明 | 触发时机 |
|------|------|---------|
| 知识点测试/课后练习 | 每讲后的基础作业 | 每讲内容解析完成后 |
| 分章真题测 | 按章节的真题练习 | 对应章节完成后 |
| 强化专题 | 针对重点难点的专题练习 | 相关章节完成后 |
| **冲刺模考** | **3张48题综合模考** | **所有课程/讲座与基础作业完成后（特殊模式，最后进行）** |

### 关键要点

- **接口主链路（正常路径）**：syllabus 枚举本章卷与完成状态 → record → redo-paper（当场拿题+标准答案+解析）→ 满足最小作答时长 → submit-paper 一次性交全卷 → exam-report 回查；契约见 [gaodun-exam-api.md](development/api/gaodun-exam-api.md)，操作入口 `scripts/cdp/api_do_paper.js`
- **题型覆盖**：
  - 客观题（type=1单选、type=2多选）：接口直给标准答案，直接提交
  - 主观题（type=5计算/综合大题容器、type=6主观自由文本小问）：从analysis提炼答案，提交后逐题AI批改冲满分；详见 [gaodun-exam-api.md](development/api/gaodun-exam-api.md)
  - 其他题型（判断/填空等）：遇到时先只读侦查接口，交互不同处单独打通
- **两条异常出口（不做常规双轨）**：①需重新登录/验证码 → 暂停交用户；②遇到没见过的卷型/题型/报错 → 不硬闯，停下发起针对性测试或功能迭代
- **作业模式与顺序**：先知识点测试/课后练习，再分章真题测、强化专题；**冲刺模考（3张48题）是特殊模式，必须在所有课程/讲座与基础作业完成后才做**，其题/答同为知识来源、但最后采集
- **作业目标 100% 正确**：接口直给标准答案，以 exam-report 全对为准；非满分视为需排查的异常（不再是"做错题更有价值"）
- **知识来源口径（2026-09-02 对齐）**：来源=初始知识库 + 题/答 + 官方解析 + 用户笔记；**自动化作业产生的 AI 错题不作来源**（旧 UI BUG 产物、非用户产出）；「考点图谱」经侦查只给章→考点目录归属、无知识点关联，**已否决、不作来源**。详见 [knowledge-base-sources.md](development/knowledge/knowledge-base-sources.md)
- **知识反哺**：题/答暴露的遗漏客观知识点→知识拆解；官方解析/真题/易错/口诀→考试指导；用户笔记与讲义冲突时以讲义为准
- **任务执行指南（接口为主、UI 兜底）**：前置准备、枚举作业与完成判据、批量/单卷命令、两层回查、异常三出口，以及接口失败时的 UI 兜底最小操作集，见 [exam-workflow.md](development/guides/exam-workflow.md)

### 冲刺模考（特殊模式，所有基础作业完成后）

> **注意**：冲刺模考是做题/交卷的一种特殊模式，必须在所有课程/讲座与基础作业完成后才进行。冲刺模考完成后，需要走后续的题/答/解析采集、知识库迭代更新、同步飞书知识库流程。

**触发条件**：
- 所有课程/讲座的视频已下载、压缩、验证
- 所有课程/讲座的讲义已下载、OCR
- 所有课程/讲座的基础作业已100%完成，题/答/解析已采集
- 所有课程/讲座的知识库已生成并同步飞书知识库
- 考试指导速查手册已生成

**冲刺模考后续流程**：
1. **冲刺模考视频解析**：走与一般课程相同的完整流程（下载→压缩→转写→OCR）
2. **冲刺模考做题/交卷**：先只读侦查接口，交互不同处单独打通；然后完成3张48题冲刺模考
3. **题/答/解析采集**：采集冲刺模考的题目、答案、解析，作为知识来源
4. **知识库迭代更新**：将冲刺模考的题/答/解析反哺知识库，更新知识拆解和考试指导
5. **更新考试指导速查手册**：将冲刺模考的高频考点、易错点汇总到考试指导速查手册（只汇总通用考点和易错点，不包含具体题目或业务场景）
6. **同步飞书知识库**：将更新后的知识库内容同步到飞书知识库

## 7. 知识库一次性生成

### 摘要

收集所有知识来源（讲义OCR + 视频转写 + 题/答/解析 + 用户笔记）后，一次性生成知识库（知识拆解 + 考试指导 + 父节点内容），不做两阶段。

### 知识来源

| 来源 | 内容 | 用途 |
|------|------|------|
| 讲义OCR结果 | 官方讲义内容（定义、分类、原则、表格） | 知识拆解的核心来源 |
| 视频转写文本 | 老师讲解内容（补充说明、例题、记忆口诀） | 知识拆解和考试指导的补充来源 |
| 题目/答案/解析 | 作业题、标准答案、官方解析 | 知识拆解（遗漏知识点）和考试指导（易错点、考点） |
| 用户笔记 | 用户在学习过程中记录的笔记 | 知识拆解和考试指导的补充（与讲义冲突时以讲义为准） |

### 生成顺序

1. **知识拆解**（第1步）：基于讲义OCR + 视频转写 + 题/答（客观知识点），生成章节核心知识点（定义、分类、原则、表格）
2. **考试指导**（第2步）：基于知识拆解 + 官方解析 + 用户笔记 + 题/答（易错点、口诀），生成应试内容（高频考点、易错点、记忆口诀、做题技巧）
3. **父节点（章节）**（第3步）：基于知识拆解 + 考试指导的摘要，生成子节点链接 + 章节概述 + 重点内容 + 学习建议
4. **父节点（课程）**（第4步）：基于所有章节的摘要，生成课程信息 + 章节列表 + 课程概述 + 学习建议
5. **考试指导速查手册**（最后，所有讲次完成后）：横向汇总所有讲次的税率表、高频考点TOP10、易错点TOP10、跨税种对比；**不包含具体指定业务的题目或场景要求**

### 生成方法论

1. **先知识后应试**：先生成知识拆解（知识本身），再生成考试指导（应试角度）；考试指导基于知识拆解，避免知识重复
2. **来源交叉验证**：讲义OCR + 视频转写 + 题/答三者交叉印证；用户留言与讲义冲突时以讲义为准；官方解析是标准答案的权威来源
3. **按知识点组织，不按视频时间线**：知识拆解按考点/知识点组织，不是按视频的时间顺序；视频中同一个知识点可能在不同时间提到，需要合并
4. **原子结构，MECE分类**：每段一个主题，不混合；分类互斥且穷尽（MECE）；关键对比内容用表格
5. **Answer-First**：每节开头有核心结论，再展开细节；方便快速浏览和AI检索
6. **区分两种生成路径**：首次从零生成走"原料搭建"；已有初始知识库时的34章重建走"**旧骨架复用 + 多源核对 + 题答校验增强**"（不推倒重写、也不照抄旧版，用本讲全部作业官方解析逐题校验、补真题细节、剔除AI错题）。单讲从原料到三文件的详细作业步骤、题答校验脚本、自检清单见 [lecture-knowledge-build-sop.md](development/guides/lecture-knowledge-build-sop.md)；首个标准样板为 `_34chapters/讲01/`。

### 关键要点

- **原则：先本地，后飞书；先验证，后同步。** 所有知识库内容的变更必须先在本地文档中完成，验证通过后再同步到飞书
- **知识库结构**：CPA/课程库/<课程名>/<章节名>/知识拆解 + 考试指导
- **节点命名**：严格对齐官方讲次标题（如"税法全面精讲02-消费税法（1）"），不擅自修改、合并或重排
- **内容分工**：知识拆解=章节核心知识点（定义、分类、原则、表格）；考试指导=做题技巧、易错点、记忆口诀、高频考点
- **父节点规范**：课程节点和章节节点必须包含子节点目录清单（可点击链接+简要说明）、章节概述、重点内容、学习建议
- **整理原则**：按知识点而非视频时间线组织；视频语音+PPT画面+讲义文档三者交叉印证；用户留言与讲义冲突时以讲义为准
- **考试指导速查手册约束**：**不包含具体指定业务的题目或场景要求**（如具体计算题、案例分析题、指定章节/税种的具体要求），只包含通用知识点和应试指导
- **禁止直接在飞书知识库中编辑内容**（除非紧急修复），必须用API同步

## 8. 同步飞书知识库

### 摘要

将本地生成的知识库内容同步到飞书知识库，执行结构检查，确保同步正确。

### 同步策略

| 同步时机 | 同步内容 | 目的 |
|---------|---------|------|
| 每讲完成后 | 该讲的知识拆解、考试指导、父节点内容 | 及时同步，避免最后一次性同步的风险，方便用户随时查看 |
| 所有讲次完成后 | 考试指导速查手册（横向汇总所有讲次） | 顶层索引页，需要所有讲次完成后才能生成 |
| 冲刺模考完成后（特殊模式） | 冲刺模考的题/答/解析、更新考试指导速查手册 | 冲刺模考是步骤5的特殊模式、所有基础作业完成后才做，完成后补充到知识库 |

### 关键要点

- **先本地生成，验证通过后再同步飞书知识库**
- 同步后必须执行结构检查：节点层级、重复节点、空节点、父节点链接、独立文档检查
- 禁止直接在飞书知识库中编辑内容（除非紧急修复），必须用API同步
- 同步失败时，先检查网络和权限，再重试；连续失败3次以上，暂停并报告

### 参考文档

- **飞书API**：[feishu-api.md](development/api/feishu-api.md) — 飞书API调用方法、权限配置、常见问题
- **知识库维护指南**：[feishu-knowledge-base-maintenance.md](development/guides/feishu-knowledge-base-maintenance.md) — 飞书知识库维护、节点管理、内容同步
