# 知识库来源清单

> **文档类型**：Reference（参考资料）
> **更新频率**：新增内容来源时
> **维护者**：AI自动维护
> **读者**：AI代理+人类

> 本文档记录知识库内容的来源，确保所有内容都可追溯、可验证。
> 原则：**本地有，则同步到知识库**。所有知识库内容必须先在本地文档中完成并验证，再同步到飞书知识库。

> **2026-09-02 口径对齐（重要）**：做题链路已由 Playwright UI 改为纯接口（redo-paper 进卷即返回题面/标准答案/解析，见 [gaodun-exam-api.md](../api/gaodun-exam-api.md)）。本次重新认定知识来源：**作业过程中因旧 UI BUG 产生的"AI 错题"不再作为知识来源**；**课程表「考点图谱」经侦查评估后否决、不作为知识来源**（它只提供"章→考点"目录归属、并不存在知识点之间的关联，结论与证据见《任务报告_知识来源对齐与考点图谱接口侦查_2026-09-02》，留此结论避免日后重复调研）。

## 一、知识库内容来源（认定版）

### 1.1 内容来源（进入知识库，共 4 类 + 1 个末期特例）

| # | 来源类型 | 来源位置 / 获取方式 | 内容 | 进入文档 |
|---|---------|--------------------|------|---------|
| 1 | **初始知识库（线A第一阶段产物）** | `knowledge-base/organized-content/<章节>/知识拆解.md`、`考试指导.md`（由视频转写+讲义+OCR 生成） | 客观知识主体，是第二阶段迭代的基础 | 知识拆解、考试指导 |
| 1a | 视频转写文字 | `data/高顿/CPA/课程库/<课程>/<讲座>/transcript.md` | 老师讲解全文 | 知识拆解、考试指导 |
| 1b | 讲义文档 | 同目录 `docs/`（PDF/PPT/DOC） | 知识点、例题、图表（最权威） | 知识拆解、考试指导 |
| 1c | 讲义OCR文字 | 同目录 `docs_text/` | 图片型讲义中的表格/图表文字 | 知识拆解 |
| 2 | **题目与标准答案** | **redo-paper 接口直给**（`questionList[].title` + `questionAnswer.answer`；落 data/cdp-sniff 或后续导出） | 题面、选项、标准答案（客观、接口保证正确） | 考试指导（真题/考点）、知识拆解（遗漏点） |
| 3 | **官方解析** | **redo-paper 接口直给**（`questionAnswer.analysis`，含 improve/translate） | 官方解题思路、答案解释 | 考试指导 |
| 4 | **用户笔记** | `knowledge-base/source-materials/<课程>/用户笔记精华_<课程>.md`（题库其他用户高赞留言/口诀） | 记忆口诀、易错点总结（主观补充） | 考试指导 |
| 特例 | **冲刺模考卷题目与标准答案** | redo-paper 同接口，卷为 48 题冲刺模考（paperId 86722/86723/86724） | 综合卷题面、标准答案、解析 | 考试指导、知识拆解 |

> **冲刺模考特例的阶段约束**：冲刺模考的题/答**同样是知识来源**，但只有在**所有前置课程与基础作业全部完成后**才会遇到、才采集与打通（见 WORKFLOW 总考试触发条件）；在此之前不做、不采。

### 1.2 明确不作为知识内容来源

| 项 | 原因 | 去向 |
|----|------|------|
| **自动化作业过程中产生的错题 /「AI 选错」** | 那是旧 Playwright UI 交互 BUG（题序/时序错位）造成的错误，**不是用户本人产出、也不是知识**；接口化后作业以 100% 正确为目标，理论上不再产生这类错题 | 仅用于排查流程/脚本 BUG，**不写入知识库** |
| **课程表「考点图谱」（knowledge-sketch）** | 2026-09-02 侦查结论：其数据（with-sid→course/point）只是 **15 章→96 考点的目录归属树**，**不含知识点之间的关联**（多父考点=0、无关联字段、点节点不发额外请求）；用户要的是知识点关联，故**否决、不作来源** | 仅留侦查结论备忘（当日任务报告），不采集、不遍历圆点 |
| 知识库质量验证结论 | 属内部质检、不是知识内容，默认并入任务报告、不单独成文 | 用于覆盖度核对、驱动补充，不直接当知识 |

> 说明：旧文档中"做错的题更有价值、用错题发现知识漏洞"是 **UI 时代**的做法（那时会真做错题）。接口直给标准答案后，"发现漏洞"改由**题/答/解析**承担，不再依赖 AI 错题。
> 若未来确实需要"知识点横向关联（交叉/前置）"，平台不直接提供，只能在知识生成阶段从题面/官方解析/讲义文本中提炼，届时另立任务，与已否决的「考点图谱」无关。

## 二、知识库文档与来源对应关系

### 2.1 知识拆解.md（客观知识）

**位置**：`knowledge-base/organized-content/<章节名>/知识拆解.md`

**内容来源**：
1. 初始知识库（视频转写为主、讲义交叉印证、OCR 补图表）——客观知识主体
2. 题目与标准答案中暴露的**遗漏知识点**（只补客观知识，不记 AI 错题）

**组织原则**：按知识点而非视频时间线组织；只保留客观知识、不含考试指导；定义/分类/原则/表格结构化；标注来源（讲义页码 / 视频时间点）。

### 2.2 考试指导.md（应试内容）

**位置**：`knowledge-base/organized-content/<章节名>/考试指导.md`

**内容来源**：
1. 视频转写中的考点提示、易错提醒
2. 讲义中的例题、真题、考情
3. **官方解析（redo 接口直给）的解题思路**
4. **题目与标准答案（redo 接口直给）形成的真题/考点库**
5. 用户笔记中的口诀、易错总结（冲突时以讲义/官方为准）

**组织原则**：按"考情分析→高频考点→易错点→记忆口诀→真题回顾→学习建议"组织；与知识拆解互引。

### 2.3 做题思路解析.md（通用方法论，不变）

位置 `knowledge-base/organized-content/做题思路解析.md`；来源为通用做题方法论与各课程经验，不含具体知识点。

### 2.4 题目/答案/解析的接口化提取规范（替代旧"做题记录辨对错"流程）

接口化后，题面、标准答案、解析在 **redo-paper 响应里一次拿全且标准答案客观正确**，不再需要旧 UI 时代"用 ✓ 人工区分 AI 选对/选错"的流程。

| 数据项 | 接口字段 | 用途 | 进入知识库 |
|--------|---------|------|-----------|
| 题面/选项 | `title`、`selectList[]` | 真题回顾 | 考试指导 |
| 标准答案 | `questionAnswer.answer` | 客观正确答案（1单/2多，多选"A,B,D"） | 考试指导、知识拆解 |
| 官方解析 | `questionAnswer.analysis` | 解题思路、考点 | 考试指导 |
| 拓展/翻译 | `improve`/`translate` | 补充理解 | 考试指导（择优） |
| 知识点标签 | `knowledgePointList` | 对齐考纲考点归属 | 知识拆解 |
| ~~AI 作答结果~~ | — | **不采集为知识**，仅在脚本 BUG 排查时看 exam-report 错题 | 不进入 |

> 做题不产出手抄 md 记录：UI 时代的 `EXAM_RECORD_TEMPLATE.md`（✓/AI选错标记、"不强求全对"）已废弃删除。题/答/解析以 `collect_paper_sources.js` 只读落盘的 `data/knowledge-source/papers/<paperId>.json` + `paper_index.json` 为客观凭据；做题结果以 `data/cdp-sniff/batch_result_*.json` 与 exam-report 回查为准。

## 三、来源选择流程与顺序

### 3.1 总体原则

- **所有知识库内容必须有来源依据，不能凭空编造**；多来源冲突按 3.2 优先级处理；重要内容标注来源。
- 第二阶段（做题迭代）在**第一阶段初始知识库**基础上补充，不推倒重来。

### 3.2 来源优先级（从高到低，2026-09-02 重排）

| 优先级 | 来源 | 角色 |
|--------|------|------|
| 1 | 讲义文档 | 最权威，冲突终裁 |
| 2 | 视频转写文字 | 与讲义交叉印证 |
| 3 | 讲义OCR文字 | 图表文字 |
| 4 | 官方解析 + 题目标准答案（接口直给） | 客观正确，应试依据 |
| 5 | 用户笔记 | 主观补充（口诀/易错），最低 |
| — | ~~AI 错题~~、~~考点图谱~~ | **不入优先级、不作来源**（见 1.2） |

### 3.3 整合顺序（按流程）

1. **收齐来源**：初始知识库（转写/讲义/OCR）＋ redo 接口的题/答/解析 ＋ 用户笔记；来源不齐先补来源。
2. **搭知识拆解**：以讲义为基础、视频/OCR 补充，题目标准答案只补"遗漏的客观知识点"。
3. **补考试指导**：从视频/讲义取考点与例题，从官方解析取思路，从题/答建真题考点，从用户笔记取口诀。
4. **验证**：对照题/答查覆盖度，结论并入任务报告（内部质检、不单独成文）。
5. **先本地后飞书**：本地验证通过再 API 同步并回读。

### 3.4 不同文档的来源选择

| 文档 | 主要来源 | 次要来源 | 不使用 |
|------|---------|-----------|--------|
| 知识拆解 | 讲义+视频+OCR | 题/答暴露的遗漏知识点 | 用户笔记、官方解析、**AI错题、考点图谱** |
| 考试指导 | 视频考点+讲义例题+官方解析+题/答 | 用户笔记 | 讲义OCR（除例题图表）、**AI错题、考点图谱** |
| 做题思路解析 | 通用方法论+做题经验 | exam-workflow | 具体知识点 |

### 3.5 冲突处理规则（不变）

讲义 > 视频转写 > 官方解析 > 用户笔记；用户笔记与知识拆解冲突时以知识拆解为准、经验证才改；视频前后不一以最后强调为准或标"待确认"；不确定不写成定论。冲突处理要记录依据。

### 3.6 来源标注要求

重要知识点标讲义页码/视频时间点；真题标来源（redo-paper / 年份）；口诀标"用户笔记（点赞N）"。格式统一为内容末尾括号标注。

## 四、知识库同步流程（不变）

**先本地，后飞书；先验证，后同步。**

```
更新本地文档 → 验证本地文档 → 同步飞书知识库（API 优先）→ 回读验证飞书
```

禁止直接在飞书编辑（紧急修复除外）；长内容优先 @file，写后必须 fetch 回读（见 [feishu-api.md](../api/feishu-api.md)）。

## 五、知识库发展与重设计原则（不变）

新增课程 / 结构调整 / 新增内容类型 / 飞书能力升级时重设计；原则：向后兼容、渐进迁移、记录变更、同步更新 WORKFLOW/organization/TASK_STATUS、验证无遗漏；先试点后推广。
