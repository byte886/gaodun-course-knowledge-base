# 知识库来源清单

> **文档类型**：Reference（参考资料）
> **更新频率**：新增内容来源时
> **维护者**：AI自动维护
> **读者**：AI代理 + 人类

> 本文档记录课程知识系统的内容来源，确保所有内容可追溯、可验证。原则：**本地有、本地验证，再同步飞书**。
> 范式基线 [ADR-012](../../project-management/decisions/ADR-012-三层解耦与按知识点聚合.md)：原料在课程目录 `原始资源/`、题答在 `data/_workspace/<profile>/papers/`、成品在 `知识详解/`（一个官方知识点一篇、篇内 4 节）。

> **口径对齐（2026-09-02 / 2026-09-04 更新）**：做题链路为纯接口（redo-paper 进卷即返回题面/标准答案/解析，见 [gaodun-exam-api.md](../api/gaodun-exam-api.md)）。①旧 UI BUG 产生的"AI 错题"**不作来源**；②课程表「考点图谱」经侦查**否决**（只给"章→考点"目录归属、无知识点关联）；③成品不再分"知识拆解.md/考试指导.md"双文档，改为知识点单篇内 4 节。

### 1.1 明确不作为来源

| 项 | 原因 | 去向 |
|----|------|------|
| **自动化作业产生的"AI 选错/错题"** | 旧 UI 交互 BUG（题序/时序错位）产物，非用户产出、非知识；接口化后以满分/最优为目标 | 仅排查脚本 BUG，**不写入成品** |
| **课程表「考点图谱」** | 侦查结论：只是章→考点目录归属树，**不含知识点关联**（用户要的是知识点关联），故否决 | 留侦查结论备忘，不采集、不遍历 |
| 质量验证结论 | 内部质检、非知识 | 驱动覆盖度核对，并入任务报告，不直接当知识 |

> 旧"用错题发现知识漏洞"是 UI 时代做法；接口直给标准答案后，"发现漏洞"由**题/答/官方解析**承担。未来若要知识点横向关联，只能在生成阶段从题面/解析/讲义文本提炼，与已否决的考点图谱无关。

## 二、来源与"知识点单篇 4 节"的对应关系

一个官方知识点 = `知识详解/NN_组/{知识点}.md`，篇内固定四节（成品结构见 [KNOWLEDGE_BASE_TEMPLATE.md 第三节](../templates/KNOWLEDGE_BASE_TEMPLATE.md)）：

| 节 | 内容 | 主要来源 |
|----|------|----------|
| 一、知识拆解 | 客观知识：定义/分类/原则/表格，按子主题、不按视频时间线 | 讲义＞转写＞OCR；题答只补"遗漏的客观点"（行内标`（真题补充：…）`） |
| 二、考试指导 | 考情、高频（**题量脚本聚合**）、易错、口诀/技巧 | 转写考点 + 官方解析 + 题答；用户口诀标注来源 |
| 三、题答解析 | 本知识点全部题：题面/选项/标准答案/官方解析 | papers（客观取顶层；**主观 type5 下钻 subQuestionList，真答案在小问 analysisText**） |
| 四、学员补充 | 高价值学员讨论/助记/易错补充，**无则整节省略** | notes-raw（去掉点赞数与采集残留） |

> 跨课的 `通用做题思路解析.md`（CPA 层）与课程全局 `课程做题思路解析.md`、`考试指导速查手册.md` 的来源：通用做题方法论 + 各知识点篇的通用提炼；**速查手册只含通用内容、不含具体指定业务的题目或场景**。

### 2.1 题/答/解析的接口字段（papers JSON）

题目在 `moduleList[].questionList[]`：

| 数据项 | 字段 | 用途 |
|--------|------|------|
| 题面/选项 | `title`(HTML)、`selectList[].optionContent` | 题答解析 |
| 标准答案 | `answer`（多选形如 "A,B,D"；主观小问常为"见解析"） | 客观正确答案 |
| 官方解析 | `analysis`(HTML) / `analysisText`（纯文本，**主观真答案在此**） | 解题思路/算式 |
| 知识点标签 | `knowledgePointList[{id,title}]` | 归 14 组 92 点的依据 |
| 题型 | `questionType`（1 单/2 多/3 判断/5 大题容器/6 小问） | 组织方式 |
| ~~AI 作答结果~~ | — | **不采集为知识**，仅排查时看 exam-report |

> 题/答不手抄成 md，以 `data/_workspace/<profile>/papers/{paperId}.json` + `paper_index.json` 为客观凭据；做题结果以 exam-report 回查为准。

## 三、来源选择流程与顺序

### 3.1 总原则
- 所有内容必须有来源依据，不凭空编造；多源冲突按 3.2；重要内容标来源。
- 在视频/讲义/OCR 主干上用题/答/解析补遗漏、迭代，不推倒重来。

### 3.2 来源优先级（高→低）
| 优先级 | 来源 | 角色 |
|--------|------|------|
| 1 | 讲义（含 OCR） | 最权威，冲突终裁 |
| 2 | 视频转写 | 与讲义交叉印证 |
| 3 | 官方解析 + 题目标准答案（接口直给） | 客观正确、应试依据 |
| 4 | 用户笔记/高赞留言 | 主观补充（口诀/易错），最低 |
| — | ~~AI 错题~~、~~考点图谱~~ | 不入优先级、不作来源 |

### 3.3 整合顺序
1. **收齐**：转写/讲义/OCR ＋ papers 题/答/解析 ＋ 用户留言原件；不齐先补；
2. **搭"一、知识拆解"**：讲义为基、视频/OCR 补充，题答只补遗漏客观点；
3. **补"二、考试指导"**：题量定高频、官方解析出思路、用户笔记出口诀；
4. **组"三、题答解析"**：按知识点聚合全部题，主观下钻小问；
5. **筛"四、学员补充"**：只留高价值增量；
6. **验证**：对照题答查覆盖度与题量对账，结论并入任务报告；
7. **先本地后飞书**：本地过门再统一同步并回读。

### 3.4 冲突处理
讲义 ＞ 转写 ＞ 官方解析 ＞ 用户笔记；用户笔记与正文冲突时以正文为准、经验证才改；转写前后不一取最后强调或标"待确认"；不确定不写定论，处理要记录依据。

### 3.5 来源标注
重要知识点标讲义页码/视频时间点；题目标来源卷（redo-paper/年份）；学员内容标"学员补充"。统一在内容末尾括号标注。

## 四、同步流程（不变）

**先本地，后飞书；先验证，后同步。**

```
更新本地 知识详解 → 过阶段③校验门 → 统一同步飞书（API 优先）→ 回读验证
```

禁止直接在飞书编辑（紧急修复除外）；长内容优先 @file，写后必须 fetch 回读（见 [feishu-api.md](../api/feishu-api.md)）。同步时机与"冲刺后最终一次"见 [finalize-sop.md](../guides/finalize-sop.md)。

## 五、发展与重设计原则

新增课程 / 结构调整 / 新来源类型 / 飞书能力升级时重设计：向后兼容、渐进迁移、记录变更、同步更新 WORKFLOW/organization/台账、验证无遗漏、先试点后推广。
