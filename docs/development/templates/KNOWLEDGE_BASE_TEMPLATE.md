# 知识库模板与规范

> **文档类型**：Template（模板骨架）
> **更新频率**：模板变更时
> **维护者**：AI自动维护 + 用户审核
> **读者**：AI代理

## 文档目的

本文档定义知识系统各级节点"成品长什么样"（静态结构）。范式基线为 [ADR-012](../../project-management/decisions/ADR-012-三层解耦与按知识点聚合.md)：**课程 → 官方模块组（父节点）→ 官方知识点单篇（一篇 4 节）**，跨讲聚合。

> **本文档只规定成品结构，配套分工（不重复堆叠）：**
> - 组织原则、分组方法、质量清单 → [knowledge-base-organization.md](../knowledge/knowledge-base-organization.md)
> - 一篇具体怎么从原料做出来（加工步骤、题答校验、自检）→ `knowledge-detail-build-sop.md`（待建，批3）
> - 哪些能当来源、冲突谁优先 → [knowledge-base-sources.md](../knowledge/knowledge-base-sources.md)
> - 在四阶段流程的位置与校验门 → [WORKFLOW.md 阶段③](../../WORKFLOW.md)
>
> 结构问题改本模板、做法问题改 SOP、来源问题改 sources、流程问题改 WORKFLOW。

## 一、知识库层级结构

```
CPA备考知识库（根）
└── 课程库
    ├── 通用做题思路解析.md                 ← 跨课通用方法论（课程库层，全课共用一份）
    └── 【26考季】VIPCPA系列-税法（蔡俊峻老师）/   ← 课程根节点
        ├── 01_税法总论/                    ← 官方模块组（父节点=目录页）
        │   ├── 税法概念.md                 ← 官方知识点单篇（一篇=一个知识点，篇内4节）
        │   ├── 税法原则.md
        │   └── …（本组 N 个知识点）
        ├── 02_增值税法/
        │   └── …
        ├── …（共 14 组、92 篇）
        ├── 课程做题思路解析.md             ← 课程全局篇（带本课程特征）
        └── 考试指导速查手册.md             ← 课程全局篇（只通用，冲刺后定稿）
```

- 层级固定 3 层：课程 / 组 / 知识点篇；知识点内部用 H2/H3，不再为子主题建页面。
- 组编号 `NN_` 按官方教材/课件模块序；知识点文件名用官方知识点原名。
- 本地 `知识详解/` 与飞书**同构**：本地目录=飞书父节点，本地 .md=飞书子页面。

## 三、知识点单篇模板（核心，一个知识点一篇）

> 固定四个二级标题：一、知识拆解 / 二、考试指导 / 三、题答解析 / 四、学员补充。**第四节无内容时整节省略**，其余三节为必备。

```markdown
# {官方知识点名}

> 所属组：{NN_组名}
> 来源：讲义 {a} 份 · 转写 {b} 讲 · 题 {c} 道（客观 {x} + 主观大题 {y}）
> 适用：26 考季 CPA 税法
> 更新：YYYY-MM-DD

---

## 一、知识拆解

### 1. {子主题}
{Answer-First：先一句核心结论，再展开；必要处用表格对比}

### 2. {子主题}
{同上；只放客观知识，不放考点提示/口诀（那些进第二节）}

## 二、考试指导

### 考情与高频
- 本点共 {c} 题（脚本按 knowledgePointList 聚合，不凭感觉），{题型分布}
- {考情定位、预计分值、出题方式}

### 易错点辨析
- ❌ {常见错误} → ✅ {正确结论}

### 记忆口诀 / 技巧
- {口诀，来自转写/讲义；若来自学员须标注}

## 三、题答解析

> 本节由脚本确定性生成（见"硬性约束"），分客观题、计算/综合大题两段；标题层级固定为
> `###（一）客观题` / `###（二）计算/综合大题` → `#### 大题N`。

### （一）客观题（{n} 道）
**{序号}.【{题型}｜来源：{卷名}（paperId {id}）】{题干}**
- A. …　- B. …　- C. …　- D. …
**答案：X**　解析：{官方解析，去 HTML}

### （二）计算 / 综合大题（{b} 道大题、{s} 个小问）
#### 大题N（N/总数）｜来源：{卷名}（paperId {id}）
> {完整大题业务题干（bigStem），引用块整段保留，不删减业务条件}

**（1）{小问题干}**
{小问 analysisText 原文：完整算式＋结果，保留【点拨】；小问 answer 常为"见解析"，真答案在此}
**（2）…**

## 四、学员补充
> 无高价值学员内容时整节省略。
- {学员高价值讨论/助记/易错补充，标注来源；与正文冲突时按 sources 权威度处理，不覆盖}

---

## 关联知识点
- [{相邻知识点}](./{同名}.md)：{一句关联说明}（同组兄弟篇用相对链接；批量时兄弟篇尚未生成可先挂前向链接，文件名取官方点名，批量后自动生效）
```

**硬性约束**：
- 主观题**必须下钻 `subQuestionList`**，禁止只取大题顶层（顶层 answer/analysis 为空会漏，真答案在小问 analysisText）。
- **题答解析由脚本确定性生成、AI 不手抄算式数字**：`collect_point_questions.py` 按知识点聚合 → `render_point_qa.py` 渲染第三节初稿；AI 只写第一/二节并校核题答，不改动题面、答案、算式本身。
- **公式与算式分工**：可复用的公式/规则/对照表放"一、知识拆解"，每道大题的具体算式演练放"三、题答解析"，两处不重复堆叠。
- **计算大题全收不折叠**：以"大题"为不可拆单位全部收录（每道是完整业务情境），不做"典型题＋其余索引"，靠 `#### 大题N` 导航；篇幅长不构成删减理由。
- 每题标注来源卷与 paperId；剔除自动化作业产生的 AI 错题。
- 篇内题数（客观数 / 大题数 / 小问数）须与 collect 聚合结果逐项对平（质量门）。
- 高频度必须由题量脚本聚合，不凭经验标星。

## 七、父节点内容同步机制

1. **触发**：新增子篇 / 子篇重大更新 / 子篇状态变化；
2. **动作**：同步父节点的子页面清单、题量、概述、重点、状态、更新时间；
3. **验证**：父节点列出的子页面与实际目录/飞书子节点一致（不缺不重、无空节点）。

## 八、节点内容生成决策树

```
新节点
 ├─ 有子节点？（课程根/模块组）→ 必须生成目录页（含子链接+摘要）
 ├─ 是知识点篇？→ 必须按四节模板生成（第四节可省）
 ├─ 是课程全局篇/导航页？→ 按对应模板生成
 └─ 其余 → 暂空，待有子节点后再生成
```
